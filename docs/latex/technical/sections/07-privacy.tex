\section{Privacy and Law 21.719}\label{sec:privacy}

Chile's Law 19.628, as amended by Law 21.719 (published 2024-12-13, in force 2026-12-01), governs personal data. Bank
statements are personal and financial data, and profiling a person's finances is likely high-risk processing. This
section maps what the software does to the law's main duties. It is engineering evidence for counsel to review, not
legal advice; article numbers follow the Library of Congress summary that \code{docs/SECURITY.md} cites.

There is no automatic retention period: data stays until the user deletes the account or the operator deletes the
database. With the default settings nothing leaves the server. A provider receives data only when its setting is on
(live mode): the language model receives the conversation and tool results; Jev receives chat messages and, for
categories, redacted charge text, never a deposit; Azure AI Language receives raw line text before redaction. All of them
are outside Chile. Four more recipients came with the newer features. Fintual (in Chile) receives the email and password
once when a user links an account, then the token on each sync. A user-added MCP server receives only its own token
and the names of the tools to call. Fintoc receives the link the user created in its widget. The DNS resolver receives
an email's domain at sign-up. The concept cards and their index stay on the server, and the Chroma container only
stores vectors.

Each built control (C01--C13 and the G rows that are built) is a plain test, and each missing duty is a strict expected
failure marked \code{GAP}: CI stays green, the gap stays visible, and the day a control lands its test passes
unexpectedly and the run fails until the marker is removed. \code{test_every_compliance_test_is_in_the_security_map}
keeps \code{docs/SECURITY.md} and the tests in step.

\subsection{The sandbox posture}

The public demo is a sandbox with open sign-up. Its privacy position rests on four things: the notice asks visitors not
to store real data and records that they agreed; whatever is stored anyway is redacted at import and sealed at rest;
its owner can delete it; and the operator has an incident runbook for real data found on the server
(\code{docs/runbooks/INCIDENT_RESPONSE.md}). None of this prevents a visitor from uploading a real statement, and data
uploaded under a shared persona is visible to every other visitor of that persona until someone resets it. Before any
use with real users, the open gaps (G02, G05, G06), the impact assessment and the transfer safeguards must be closed.
