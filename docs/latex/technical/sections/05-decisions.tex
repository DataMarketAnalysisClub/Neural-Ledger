\section{Key design decisions}\label{sec:decisions}

The decision log (\code{docs/DECISIONS.md}) has 38 records. This section restates the ten that shape the system most,
in the log's format: context, decision, consequences. The status is the log's own. Several decisions are still
``Proposed'' although their code is built and tested: the team marks a record ``Accepted'' at a sync, and some have
not been through one yet.

\newcommand{\adr}[3]{\subsection*{#1 \textperiodcentered{} #2}\addcontentsline{toc}{subsection}{#1 \textperiodcentered{} #2}\noindent\textit{Status: #3.}\par}

\adr{ADR-001}{Clean architecture with a standard-library core}{Proposed}
\field{Context} Five people, ten days, and undecided providers for the language model, the decision model, storage
and the client.
\field{Decision} \code{domain} and \code{application} use only the standard library; everything external is a port
with an offline adapter; one composition root. Enforced by \code{tests/architecture}.
\field{Consequences} A provider swap is one adapter file. Slightly more structure than a script, mitigated by the
recipes in \code{docs/ARCHITECTURE.md}.

\adr{ADR-003}{The application orchestrates; the language model is an adapter}{Proposed}
\field{Context} An early diagram put the language model in front of everything, in the control path of actions.
\field{Decision} Use cases own the flow. The decision model classifies the raw text independently of the language
model, which only chooses the tools allowed in the turn and writes text. Execution reads terms from the stored
authorization.
\field{Consequences} A fully compromised model cannot move money; test S01 checks it with a hostile fake model.

\adr{ADR-004}{A decision-model port of closed questions, in a configurable chain}{Proposed}
\field{Decision} The port asks closed questions (choice, score, yes/no) and returns a label, probabilities and a
confidence. Adapters: keyword rules (always available) and Jev. \code{NL_DECISION_CHAIN} sets the order; when every
model is unavailable, the turn is read-only.
\field{Consequences} ``Jev first or rules first'' is configuration, and no money decision depends on any model.

\adr{ADR-006}{Offline mode is a requirement}{Proposed}
\field{Decision} The scripted language model and the rules decision model run the whole demo arc without keys or
network.
\field{Consequences} Reproducible CI and recordings, outages covered (S10), and judges can run the system with
\texttt{docker compose up}.

\adr{ADR-008}{HMAC-signed authorizations and a hash-chained audit log}{Proposed}
\field{Decision} \code{action_hash} $=$ HMAC-SHA256(server secret, canonical terms); audit events chained by
\code{prev_hash} and \code{event_hash}; an execution starts only after its audit event is written.
\field{Consequences} Tampered terms (S05) and edited audit events are detected; the exported log is evidence anyone can
verify. Option B adds tombstones to the chain (ADR-038).

\adr{ADR-013}{Content-addressed snapshot ids and a parameter lock}{Proposed}
\field{Decision} A ledger's \code{source_version} hashes its canonical content; every \code{snapshot_id} hashes
\code{source_version}, \code{as_of} and \code{params_version}; \code{FinanceParams.fingerprint()} is pinned per version
in a test.
\field{Consequences} One peso anywhere changes the snapshot id, and the audit's \code{forecast_snapshot_id} and
\code{policy_version} always name the data and the numbers used.

\adr{ADR-020}{Reconciliation is the authority over the reader}{Built}
\field{Decision} The domain recomputes totals and balances from the lines and compares them with what the bank printed.
Low OCR confidence only warns.
\field{Consequences} Amounts are trusted because they add up, never because a reader was confident; descriptions are the
only thing reconciliation cannot check.

\adr{ADR-028}{Personal data is removed from a statement once, at import}{Built}
\field{Context} Statement descriptions carry names, RUTs, account and card numbers, emails and phones.
\field{Decision} Deterministic rules, plus an optional detector that can only add masking, run before anything is
stored, classified, audited or returned. An import that cannot be redacted stores nothing.
\field{Consequences} No surface (API, audit, database, logs, model) sees the raw text; test S15 checks every surface.
Rules are written for Chilean statements, and a name outside a transfer line can slip through.

\adr{ADR-037}{The user's own liquidity floor}{Built, needs Roles A and B review}
\field{Decision} A floor is an action like a savings rule: proposed by the copilot, confirmed by the user, executed in
the sandbox bank. Its amount is accepted only if the user wrote it in the same turn. The latest floor rule replaces the
register's 150{,}000 for that user in every computation, and enters the snapshot id.
\field{Consequences} \code{params_version} is unchanged and the golden answers do not move; Role A must confirm that a
floor below the register's suits the capacity bands.

\adr{ADR-038}{Option B: open sign-up, explicit sandbox, everything sealed, deletable accounts}{Built on \code{security/option-b-hardening}}
\field{Context} Anyone can create an account on the public demo, so a visitor could store a real cartola. Profiles,
proposals, rules, the audit chain and the email were plain text, and the offline key file sat on the database's
volume.
\field{Decision} Keep sign-up open, but: a notice that cannot be dismissed, with a server-checked acknowledgement; the
key from a Docker secret, refused on the data volume in deployed mode; every personal payload sealed, with HKDF
subkeys and an HMAC blind index for the email; account deletion with audit tombstones; demo personas reset, never
deleted. It replaces step 6 of ADR-033 (one route instead of two, and erased events instead of kept ones).
\field{Consequences} One migration per server; losing the key loses the data; the host stays out of scope; a notice is
a rule, not a control (\cref{sec:security}).
